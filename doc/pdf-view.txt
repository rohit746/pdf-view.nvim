*pdf-view.txt*  Read PDFs inside Neovim

==============================================================================
INTRODUCTION                                                     *pdf-view*

pdf-view.nvim shows PDF pages as images inside a normal buffer. Pages are
rendered with MuPDF's `mutool` and drawn with the Kitty graphics protocol
(Unicode placeholders), so the page follows splits, tabs and resizes. In
WezTerm, Konsole and zellij the page is placed at its window's position
instead, see |pdf-view-positioned| and |pdf-view-zellij|. iTerm2 and VS Code
get iTerm2 inline images, see |pdf-view-iterm2|. foot, Windows Terminal,
xterm, Contour and mlterm get sixel, see |pdf-view-sixel|. Elsewhere the
viewer shows the text of the page, see |pdf-view-text-only|.

Requirements: Neovim 0.11+, 'termguicolors', `mutool` (with JavaScript), and
kitty or Ghostty (optionally inside tmux, or zellij 0.45+), WezTerm, Konsole,
iTerm2, VS Code, or a terminal with sixel. Run `:checkhealth pdf-view`.

==============================================================================
USAGE                                                      *pdf-view-usage*

                                                                  *:PdfView*
:PdfView {file}         Open the PDF {file} in the current window. Without an
                        argument the current buffer is used if its
                        extension is one of `extensions`.

With |pdf-view-config| `auto_open` (the default) every `*.pdf` that is read
(`:edit`, `nvim file.pdf`, |:split|, ...) becomes a viewer.
|:read| of such a file is refused, since it would insert the file's bytes
into the buffer: use |:PdfView| to open it.

Comic book archives (`*.cbz`), XPS documents (`*.xps`) and e-books (`*.epub`,
`*.fb2`, `*.mobi`) open the same way, and the extension is matched in any
case (`.PDF`, `.Cbz`). The `extensions` option sets the list. |:PdfView|
{file} takes any file MuPDF can open.

E-books have no pages of their own: they are laid out on pages as large as
the window, with text about the size of the terminal's (`text_scale`
changes it). When the window changes size the book is laid out again and
the viewer stays at the same point of the text. Page numbers change with
the layout, so marks and the jump list may point elsewhere afterwards.

The viewer is a buffer named after the file with 'buftype' `nofile` and
'filetype' `pdf-view`. Its winbar shows "<file>  <page> / <pages>".

A PDF opens at the page, fit and zoom it was left at, also after Neovim is
restarted: the last 100 are kept in
`stdpath("state")/pdf-view/positions.json`. Set `remember_position = false`
to always start on the first page.

A password-protected PDF asks for its password with |inputsecret()| when it
opens. The password is kept until Neovim exits, so reopening the PDF does
not ask again, and it reaches `mutool` on standard input, never on a command
line. Cancel the prompt (or give an empty password) to leave the PDF locked;
|:edit| asks again.

`:w` never overwrites the PDF. |:w| {file} and |:saveas| {file} save a copy
of it; after |:saveas| the viewer shows the copy. A range or |:w_a| is
refused.

A session (|:mksession|) brings the viewer back only when 'sessionoptions'
has "blank", as it does by default. Without it the session leaves the
viewer's window out.

                                                              *pdf-view-keys*
All keys are buffer-local and normal mode. The keys that move, zoom or step
between matches accept a count.

  j <Down>                scroll down; at the bottom edge, or when not zoomed,
                          next page ({count} times)
  k <Up>                  scroll up; at the top edge, or when not zoomed,
                          previous page
  l <Right>               scroll right; at the right edge, or when not
                          zoomed, next page
  h <Left>                scroll left; at the left edge, or when not zoomed,
                          previous page
  <ScrollWheelDown> etc.  like j k l h, while a viewer has focus: moves the
                          viewer under the mouse (keymaps `scroll_down`,
                          `scroll_up`, `scroll_right`, `scroll_left`)
  <PageDown> <C-f>        next page, always ({count} pages ahead)
  <PageUp> <BS> <C-b>     previous page, always
  gg <Home>               first page, or page {count}
  G <End>                 last page, or page {count}
  + =                     zoom in ({count} steps)
  -                       zoom out; from a width/height/content fit, to the
                          whole page
  0                       fit the whole page to the window
  w                       fit the page's width to the window
  W                       fit the page's height to the window
  c                       fit the page's content to the window, cropping
                          the margins
  /                       search forward (prompts for text)
  ?                       search backward
  n N                     next / previous match ({count} matches)
  <Esc>                   remove the search highlights
  gO                      pick a bookmark and go to its page
  f                       pick a link on the page and follow it
  y                       yank the page's text, linewise, into the register
                          given (`"+y` for the clipboard)
  t                       show the page's text in a scratch split
  <C-o>                   back through the jump list ({count} jumps)
  <C-i> <Tab>             forward through the jump list
  m{a-z}                  mark the page, with its fit, zoom and view
  '{a-z} `{a-z}           go to a mark
  '' ``                   back to where the latest jump started
  <2-LeftMouse>           open the TeX source at the line the point under
                          the mouse was typeset from: see |pdf-view-synctex|
  d                       show facing pages side by side, or one page at a
                          time: see |pdf-view-spread|
  i                       recolour the pages (dark mode), or stop: see
                          |pdf-view-recolor|
  r                       re-render the current page
  q                       close the viewer
  g?                      show the keys

                                                              *pdf-view-zoom*
Zoom 1 is the whole page fitted to the window; each `+` (see |pdf-view-keys|)
makes it `zoom_step` times larger, up to `max_zoom`. Zooming keeps the middle of the
window in the middle. Once the page is larger than the window a movement key
scrolls it if it can and turns the page if it cannot: scrolling down past the
bottom lands at the top of the next page, scrolling up past the top lands at
the bottom of the previous one. The zoom stays when pages turn or the file
reloads, and the winbar shows it.

                                                                *pdf-view-fit*
`w` fits the page's width to the window (starting at the top of the page) and
`W` fits its height. Each page is fitted by its own size, and the mode
survives resizes and page turns. Zoom multiplies the fitted size: `-` steps
back to the fitted size and then to the whole page, `0` goes there directly.

                                                         *pdf-view-continuous*
With `continuous = true`, scrolling goes on past the end of a page into the
next one, with the bottom of one and the top of the next on screen
together, and `k` back up into the previous one. It applies wherever `j`
and `k` scroll (a zoomed or width-fitted page); a page that fits the window
still turns. The winbar, `y`, `t` and `f` go by the page at the top of the
window, and jumps start at the top of their page.

`c` fits the part of the page that is not white (text, images, figures),
plus a few points of paper, so wide margins are cropped away. Each page is
cropped to its own content, found the first time the page is shown in this
mode and remembered until the file changes. Zoomed in, the view scrolls over
the content only. A page with a coloured background is shown whole.

                                                              *pdf-view-search*
`/` and `?` prompt (via |vim.ui.input()|) for text and search the whole
document, ignoring case. Every match on the page is highlighted, the current
one in another colour (see `highlight`), and the winbar shows "/text 3/17"
("/text searching…" while the search runs). `n` and `N` step between matches
across pages, wrapping around; a zoomed or fitted view scrolls only when the
match is not already on screen, and `+` on a fitted page zooms in towards the
current match. `<Esc>` clears the highlights. At most `search_limit` matches
are collected. The search repeats itself when the file changes.

Searches are added to the search history (|:history| /). An empty answer to
the prompt searches again for the last text searched in that viewer, like
`/<CR>` in Vim.

                                                            *pdf-view-outline*
`gO` lists the document's bookmarks through |vim.ui.select()|, indented by
depth, and goes to the chosen page. A zoomed or width-fitted page starts
with the point the bookmark leads to at the top of the window.

                                                             *pdf-view-links*
`f` lists the links on the page on screen, top to bottom, with the text
under each and where it leads, through |vim.ui.select()|. A link to a page
of the document goes there (a jump, so `<C-o>` comes back), with the point
it leads to at the top of the window when the page is zoomed or fitted to
its width; a web address or an e-mail opens with |vim.ui.open()|. Any
other address, such as a `file:` address or a PDF's Launch action, could
start a program, so `f` shows it in full and asks before opening it. The
`link_schemes` option lists the schemes that open without asking
(`http`, `https` and `mailto` by default, matched ignoring case). A page
without links says so.

                                                              *pdf-view-text*
`y` yanks the text of the page on screen into the register given (`"+y` for
the clipboard, `"ay` for register a), linewise: a line per line of text and
an empty line between blocks. `t` shows the same text in a scratch buffer in
a vertical split next to the viewer, to quote from or search with Neovim's
own tools. Each document has one such buffer, named after the page it holds:
`t` on another page fills it with that page and goes back to its split. A
scanned page has no text and says so.

                                                              *pdf-view-marks*
`gg`, `G`, `{count}G`, outline picks, search matches and marks are jumps. Each
viewer keeps a jump list of where they started: `<C-o>` goes back through
it, `<C-i>` forward, and `''` swaps with the position before the latest jump.
Past either end of that list, `<C-o>` and `<C-i>` go on through Vim's own
|jumplist|, back to the file the document was opened from. Page turns and
scrolling are not jumps. `m{a-z}` marks the page with its fit, zoom and
view, and `'{a-z}` or `` `{a-z} `` goes back to it. Marks and the jump list
belong to the viewer and stay through |:edit|.

                                                             *pdf-view-spread*
`d` shows two facing pages side by side, and `d` again one page at a time.
`spread` says how pages pair up, and whether a document starts out that
way: "on" pairs pages 1 and 2, 3 and 4; "cover" shows page 1 alone, then 2
and 3, 4 and 5, as a book with a cover opens. `d` pairs them as "on" when
`spread` is "off". The pair is fitted, zoomed and scrolled as one page, and
page turns move two pages. Search, links, the page text and SyncTeX cover
both pages. E-books show one page at a time.

                                                            *pdf-view-recolor*
`i` recolours the pages, and `i` again shows them as they are. `recolor`
says how, and whether the pages start out recoloured: "invert" inverts the
brightness but keeps the hues (black paper, white text, a red figure stays
red; also what `i` does when `recolor` is "off"), and "colorscheme" draws
black in the text colour of the |hl-Normal| group and white in its background,
so the page blends in with the colorscheme. Those pages are drawn again on
|ColorScheme|. Search highlights are recoloured with the page.

                                                            *pdf-view-synctex*
                                                            *:PdfViewForward*
For a LaTeX document built with SyncTeX on (`latexmk -synctex=1`, which
vimtex does by default, `pdflatex -synctex=1`, `tectonic --synctex`), the
viewer goes from the source to the PDF and back with the `synctex` tool of
TeX Live and MiKTeX (the `synctex` option names it).

:PdfViewForward [{file}]
                        Forward search: show where the cursor's line of the
                        TeX file in the current buffer is typeset. The page
                        is shown with the line highlighted and, zoomed or
                        fitted to the width, in the middle of the window. The
                        cursor stays in the source; a PDF that is in no
                        window opens in a vertical split. The PDF is {file},
                        else vimtex's, else one open in a viewer whose
                        SyncTeX data has the line, else the PDF named after
                        the TeX file. `<Esc>` in the viewer removes the
                        highlight, and `<C-o>` there goes back.

Double-click a point of a page (keymap `inverse_search`) for inverse search:
the source opens at the line the point was typeset from, in a window that
shows that file, else in the previous window, else in a vertical split.

To use it in place of vimtex's own viewer: >lua
    vim.g.vimtex_view_enabled = 0
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "tex",
      callback = function(args)
        vim.keymap.set("n", "<localleader>lv", "<Cmd>PdfViewForward<CR>",
          { buffer = args.buf })
      end,
    })
<

==============================================================================
LUA API                                                      *pdf-view-api*

require("pdf-view").setup({opts})                    *pdf-view.setup()*
    Configure the plugin; optional. See |pdf-view-config|. Calling it again
    also gives open viewers the new `keymaps`, `live_reload` and
    `reload_delay`.

require("pdf-view").open({path})                     *pdf-view.open()*
    Open {path} in the current window. Errors if it is not a readable file.

require("pdf-view").reload({buf})                    *pdf-view.reload()*
    Re-render the page shown in {buf} (default: current buffer).

require("pdf-view").forward_search({opts})   *pdf-view.forward_search()*
    Forward search, as |:PdfViewForward|. {opts} may name the `pdf`, and
    the `file`, `line` and `col` to show in place of the current buffer and
    the cursor.

require("pdf-view").status({buf})                    *pdf-view.status()*
    Returns "page / pages" for a viewer buffer ("page / pages width x1.25"
    while fitted to the width and zoomed), "" otherwise. Handy in a
    statusline: `%{v:lua.require'pdf-view'.status()}`.

==============================================================================
CONFIGURATION                                              *pdf-view-config*

>lua
    require("pdf-view").setup({
      auto_open = true,        -- take over *.pdf buffers
      extensions = { "pdf", "cbz", "xps", "epub", "fb2", "mobi" },
      live_reload = true,      -- re-render when the file changes on disk
      reload_delay = 200,      -- ms the file must stay quiet before reloading
      winbar = true,           -- page indicator in the winbar
      hide_cursor = true,      -- hide the cursor while a viewer is focused
      remember_position = true, -- reopen at the last page, also after a restart
      mutool = "mutool",
      synctex = "synctex",     -- for |pdf-view-synctex|
      transmission = "auto",   -- "auto" | "file" | "direct"
      tmux_passthrough = true, -- tmux set -p allow-passthrough on
      placement = "auto",      -- "auto" | "placeholders" | "positioned"
      protocol = "auto",       -- "auto" | "kitty" | "iterm2" | "sixel"
      force = false,           -- skip terminal detection
      max_pixels = 4096,       -- cap for either side of a fitted page
      zoom_step = 1.25,        -- factor of one zoom step
      max_zoom = 8,            -- largest zoom, relative to the fitted page
      pan_step = 0.2,          -- one scroll key moves this fraction of the window
      search_limit = 5000,     -- stop collecting matches after this many
      link_schemes = { "http", "https", "mailto" }, -- see |pdf-view-links|
      text_scale = 1,          -- e-book text size, relative to the terminal's
      highlight = { match = "#ffe14d", current = "#ff8c1a" },
      recolor = "off",         -- "off" | "invert" | "colorscheme"
      continuous = false,      -- scroll on into the next page, see
                               -- |pdf-view-continuous|
      spread = "off",          -- "off" | "on" | "cover", see |pdf-view-spread|
      cell_size = nil,         -- { width, height } px if undetectable
      keymaps = { ... },       -- see README; `false` disables all
    })
<

Unknown or mistyped options raise an error.

==============================================================================
POSITIONED PLACEMENTS                                  *pdf-view-positioned*

WezTerm and Konsole have the Kitty graphics protocol but not its Unicode
placeholders. There the buffer is left blank and the page is placed at the
screen position of its window, cut around floating windows and the popup
menu, and placed again after Neovim redraws the window. 'termguicolors' is
not needed.

The terminal is asked once whether it has Kitty graphics. WezTerm answers
only with `config.enable_kitty_graphics = true` in wezterm.lua; without it
the viewer says so. Konsole hides an image under any cell background but its
own, so there the page is drawn over the text, and it is sent as bytes
because Konsole reads no image files.

Inside tmux the page goes to the outer terminal at the position of Neovim's
pane, and is taken away when the tmux window is left: that needs
`set -g focus-events on` in tmux.conf.

Another terminal with Kitty graphics can be tried with
`placement = "positioned"`; it is asked as well.

==============================================================================
ITERM2 AND VS CODE                                         *pdf-view-iterm2*

iTerm2 and VS Code's terminal have no Kitty graphics, but they draw iTerm2
inline images (OSC 1337). They are recognised by `$TERM_PROGRAM` (iTerm2
also by `$LC_TERMINAL`, which ssh passes on), and inside tmux by the name the
terminal gave tmux. VS Code needs `"terminal.integrated.enableImages": true`
in its settings and the WebGL renderer (`terminal.integrated.gpuAcceleration`
not "off"). With Neovim 0.12 VS Code is asked whether it shows images, and
when it does not, the viewer says how to turn them on and shows the text of
the page instead of a blank window.

Such an image is printed into the cells at the window's position, and goes
when they are written over: Neovim drawing the window, a message that
scrolls the screen. The page is printed again after that, each time with the
whole PNG, which costs more than a Kitty placement, over SSH especially.
Around a floating window or the popup menu the page is printed in parts,
each cut out of the rendered page by mutool. What a page leaves uncovered
is erased; when that may be under another window (a split, a hidden
viewer), the screen is cleared and drawn again (|:mode|). Inside tmux an image
passes through in one piece, and tmux drops one over its input buffer: a page
whose PNG is over about 750 KB stays blank unless the buffer is raised with
`set -s input-buffer-size 4194304` (tmux 3.6).

`protocol = "iterm2"` uses these images in another terminal that draws them.
WezTerm and Konsole draw them too, but keep Kitty graphics by default.

==============================================================================
SIXEL                                                       *pdf-view-sixel*

foot, Windows Terminal (1.22+), xterm, Contour and mlterm draw sixel images.
They are recognised by `$TERM`, `$TERMINAL_NAME`, `$MLTERM`, `$WT_SESSION` and
`$XTERM_VERSION`, and inside tmux by the name the terminal gave tmux. On
Neovim 0.12 a terminal that is not recognised is asked for its device
attributes (DA1), and gets sixel when it lists it. 'termguicolors' is not
needed.

A sixel image is printed and kept in step with the screen like an iTerm2
image (|pdf-view-iterm2|). It is drawn pixel for pixel, so every part of the
page is cut out by mutool at its size on screen and encoded once, in Lua,
with a fixed palette. The cell size must be right: where the terminal does
not report it, set `cell_size`. xterm draws sixel only as a VT340
(`xterm -ti vt340`, or `XTerm*decTerminalID: vt340`). Sixel is larger than a
PNG; inside tmux, raise tmux's input buffer as for iTerm2 images.

`protocol = "sixel"` uses sixel in another terminal. WezTerm and Konsole
draw it too, but keep Kitty graphics by default.

==============================================================================
TERMINALS WITHOUT IMAGES                                *pdf-view-text-only*

In a terminal that can show no images, the viewer says why at the top of the
window and shows the text of the page under it. The page keys turn the pages,
and `<C-e>`, `<C-y>`, `<C-d>` and `<C-u>` scroll a page's text that is taller
than the window.

==============================================================================
ZELLIJ                                                     *pdf-view-zellij*

zellij 0.45 implements the Kitty graphics protocol itself, but not Unicode
placeholders. Inside zellij (`$ZELLIJ` is set) the buffer is left blank and
the page is placed at the screen position of its window. It is cut around
floating windows and the popup menu, taken away while its window is hidden
or in another tab page, and placed again after Neovim redraws the window. A
page that zellij forgot (scrolled away by a long message, say) is sent again.
'termguicolors' is not needed.

Differences: page turns are slower, because zellij forwards images as raw
pixels; only one window shows the page when the same PDF is in several
windows of a tab page; and text that the page is not cut around shows on top
of it. In zellij 0.45.1 the page is sent again whenever a float over it moves
or changes size.

`placement` chooses explicitly: "placeholders" (the default in kitty and
Ghostty outside zellij) or "positioned" (the default inside zellij, and in
WezTerm and Konsole).

==============================================================================
SNACKS.NVIM                                              *pdf-view-snacks*

snacks.nvim's image module also claims `*.pdf` buffers. Remove "pdf" from
`image.formats` in the snacks options so only one handler draws the page.
`:checkhealth pdf-view` reports a conflict.
