*pdf-view.txt*  Read PDFs inside Neovim

==============================================================================
INTRODUCTION                                                     *pdf-view*

pdf-view.nvim shows PDF pages as images inside a normal buffer. Pages are
rendered with MuPDF's `mutool` and drawn with the Kitty graphics protocol
(Unicode placeholders), so the page follows splits, tabs and resizes. Inside
zellij the page is placed at its window's position instead, see
|pdf-view-zellij|.

Requirements: Neovim 0.11+, 'termguicolors', `mutool` (with JavaScript), and
kitty or Ghostty (optionally inside tmux, or zellij 0.45+). Run
`:checkhealth pdf-view`.

==============================================================================
USAGE                                                      *pdf-view-usage*

                                                                  *:PdfView*
:PdfView {file}         Open the PDF {file} in the current window. Without an
                        argument the current buffer is used if its
                        extension is one of `extensions`.

With |pdf-view-config| `auto_open` (the default) every `*.pdf` that is read
(`:edit`, `nvim file.pdf`, |:split|, ...) becomes a viewer.

Comic book archives (`*.cbz`) and XPS documents (`*.xps`) open the same way,
and the extension is matched in any case (`.PDF`, `.Cbz`). The `extensions`
option sets the list. |:PdfView| {file} takes any file MuPDF can open.
Reflowable formats (EPUB, FB2, MOBI) are not supported yet.

The viewer is a buffer named after the file with 'buftype' `nofile` and
'filetype' `pdf-view`. Its winbar shows "<file>  <page> / <pages>".

A PDF opens at the page, fit and zoom it was left at, also after Neovim is
restarted: the last 100 are kept in
`stdpath("state")/pdf-view/positions.json`. Set `remember_position = false`
to always start on the first page.

`:w` never overwrites the PDF. |:w| {file} and |:saveas| {file} save a copy
of it; after |:saveas| the viewer shows the copy. A range or |:w_a| is
refused.

                                                              *pdf-view-keys*
All keys are buffer-local and normal mode. The keys that move, zoom or step
between matches accept a count.

  j <Down>                scroll down; at the bottom edge, or when not zoomed,
                          next page ({count} times)
  k <Up>                  scroll up; at the top edge, or when not zoomed,
                          previous page
  l <Right>               scroll right; at the right edge, or when not
                          zoomed, next page
  h <Left>                scroll left; at the left edge, or when not zoomed,
                          previous page
  <ScrollWheelDown> etc.  like j k l h, while a viewer has focus: moves the
                          viewer under the mouse (keymaps `scroll_down`,
                          `scroll_up`, `scroll_right`, `scroll_left`)
  <PageDown> <C-f>        next page, always ({count} pages ahead)
  <PageUp> <BS> <C-b>     previous page, always
  gg <Home>               first page, or page {count}
  G <End>                 last page, or page {count}
  + =                     zoom in ({count} steps)
  -                       zoom out; from a width/height/content fit, to the
                          whole page
  0                       fit the whole page to the window
  w                       fit the page's width to the window
  W                       fit the page's height to the window
  c                       fit the page's content to the window, cropping
                          the margins
  /                       search forward (prompts for text)
  ?                       search backward
  n N                     next / previous match ({count} matches)
  <Esc>                   remove the search highlights
  gO                      pick a bookmark and go to its page
  <C-o>                   back through the jump list ({count} jumps)
  <C-i> <Tab>             forward through the jump list
  m{a-z}                  mark the page, with its fit, zoom and view
  '{a-z} `{a-z}           go to a mark
  '' ``                   back to where the latest jump started
  r                       re-render the current page
  q                       close the viewer
  g?                      show the keys

                                                              *pdf-view-zoom*
Zoom 1 is the whole page fitted to the window; each `+` (see |pdf-view-keys|)
makes it `zoom_step` times larger, up to `max_zoom`. Zooming keeps the middle of the
window in the middle. Once the page is larger than the window a movement key
scrolls it if it can and turns the page if it cannot: scrolling down past the
bottom lands at the top of the next page, scrolling up past the top lands at
the bottom of the previous one. The zoom stays when pages turn or the file
reloads, and the winbar shows it.

                                                                *pdf-view-fit*
`w` fits the page's width to the window (starting at the top of the page) and
`W` fits its height. Each page is fitted by its own size, and the mode
survives resizes and page turns. Zoom multiplies the fitted size: `-` steps
back to the fitted size and then to the whole page, `0` goes there directly.

`c` fits the part of the page that is not white (text, images, figures),
plus a few points of paper, so wide margins are cropped away. Each page is
cropped to its own content, found the first time the page is shown in this
mode and remembered until the file changes. Zoomed in, the view scrolls over
the content only. A page with a coloured background is shown whole.

                                                              *pdf-view-search*
`/` and `?` prompt (via |vim.ui.input()|) for text and search the whole
document, ignoring case. Every match on the page is highlighted, the current
one in another colour (see `highlight`), and the winbar shows "/text 3/17"
("/text searching…" while the search runs). `n` and `N` step between matches
across pages, wrapping around; a zoomed or fitted view scrolls only when the
match is not already on screen, and `+` on a fitted page zooms in towards the
current match. `<Esc>` clears the highlights. At most `search_limit` matches
are collected. The search repeats itself when the file changes.

Searches are added to the search history (|:history| /). An empty answer to
the prompt searches again for the last text searched in that viewer, like
`/<CR>` in Vim.

                                                            *pdf-view-outline*
`gO` lists the document's bookmarks through |vim.ui.select()|, indented by
depth, and goes to the chosen page.

                                                              *pdf-view-marks*
`gg`, `G`, `{count}G`, outline picks, search matches and marks are jumps. Each
viewer keeps a jump list of where they started: `<C-o>` goes back through
it, `<C-i>` forward, and `''` swaps with the position before the latest jump.
Page turns and scrolling are not jumps. `m{a-z}` marks the page with its
fit, zoom and view, and `'{a-z}` or `` `{a-z} `` goes back to it. Marks and
the jump list belong to the viewer and stay through |:edit|.

==============================================================================
LUA API                                                      *pdf-view-api*

require("pdf-view").setup({opts})                    *pdf-view.setup()*
    Configure the plugin; optional. See |pdf-view-config|. Calling it again
    also gives open viewers the new `keymaps`, `live_reload` and
    `reload_delay`.

require("pdf-view").open({path})                     *pdf-view.open()*
    Open {path} in the current window. Errors if it is not a readable file.

require("pdf-view").reload({buf})                    *pdf-view.reload()*
    Re-render the page shown in {buf} (default: current buffer).

require("pdf-view").status({buf})                    *pdf-view.status()*
    Returns "page / pages" for a viewer buffer ("page / pages width x1.25"
    while fitted to the width and zoomed), "" otherwise. Handy in a
    statusline: `%{v:lua.require'pdf-view'.status()}`.

==============================================================================
CONFIGURATION                                              *pdf-view-config*

>lua
    require("pdf-view").setup({
      auto_open = true,        -- take over *.pdf buffers
      extensions = { "pdf", "cbz", "xps" }, -- what auto_open takes
      live_reload = true,      -- re-render when the file changes on disk
      reload_delay = 200,      -- ms the file must stay quiet before reloading
      winbar = true,           -- page indicator in the winbar
      hide_cursor = true,      -- hide the cursor while a viewer is focused
      remember_position = true, -- reopen at the last page, also after a restart
      mutool = "mutool",
      transmission = "auto",   -- "auto" | "file" | "direct"
      tmux_passthrough = true, -- tmux set -p allow-passthrough on
      placement = "auto",      -- "auto" | "placeholders" | "positioned"
      force = false,           -- skip terminal detection
      max_pixels = 4096,       -- cap for either side of a fitted page
      zoom_step = 1.25,        -- factor of one zoom step
      max_zoom = 8,            -- largest zoom, relative to the fitted page
      pan_step = 0.2,          -- one scroll key moves this fraction of the window
      search_limit = 5000,     -- stop collecting matches after this many
      highlight = { match = "#ffe14d", current = "#ff8c1a" },
      cell_size = nil,         -- { width, height } px if undetectable
      keymaps = { ... },       -- see README; `false` disables all
    })
<

Unknown or mistyped options raise an error.

==============================================================================
ZELLIJ                                                     *pdf-view-zellij*

zellij 0.45 implements the Kitty graphics protocol itself, but not Unicode
placeholders. Inside zellij (`$ZELLIJ` is set) the buffer is left blank and
the page is placed at the screen position of its window. It is cut around
floating windows and the popup menu, taken away while its window is hidden
or in another tab page, and placed again after Neovim redraws the window. A
page that zellij forgot (scrolled away by a long message, say) is sent again.
'termguicolors' is not needed.

Differences: page turns are slower, because zellij forwards images as raw
pixels; only one window shows the page when the same PDF is in several
windows of a tab page; and text that the page is not cut around shows on top
of it. In zellij 0.45.1 the page is sent again whenever a float over it moves
or changes size.

`placement` chooses explicitly: "placeholders" (the default outside zellij)
or "positioned" (the default inside it).

==============================================================================
SNACKS.NVIM                                              *pdf-view-snacks*

snacks.nvim's image module also claims `*.pdf` buffers. Remove "pdf" from
`image.formats` in the snacks options so only one handler draws the page.
`:checkhealth pdf-view` reports a conflict.
